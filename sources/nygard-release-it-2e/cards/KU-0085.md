# KU-0085: Chaos engineering as hypothesis-driven validation

## Purpose
Discover systemic weaknesses by deliberately introducing controlled failures and checking whether steady-state expectations hold.

## Trigger
The system has established observability, safe abort controls, and a resilience hypothesis worth testing.

## Procedure
1. Define steady-state behavior and user-impact measure.
2. Form a failure hypothesis.
3. Run the smallest safe experiment in an appropriate environment.
4. Observe impact, stop if safety limits are crossed, and analyze results.
5. Fix the weakness and repeat the experiment.

## Checks
- Steady state is measurable before the experiment.
- Blast radius and abort conditions are explicit.
- Findings create remediation and regression evidence.

## Anti-patterns
- Treating chaos as random destruction.
- Running experiments before basic monitoring and recovery exist.
