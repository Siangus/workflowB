# KU-0077: Operational transparency and control

## Purpose
Make running instances inspectable and controllable so failures can be diagnosed and mitigated without code changes.

## Trigger
A service runs across multiple instances, hosts, containers, or environments.

## Procedure
1. Expose health, readiness, dependency, configuration, and version information.
2. Provide structured logs, metrics, and correlation identifiers.
3. Provide safe operational controls such as drain, restart, disable, or traffic shift.
4. Keep control actions audited and bounded.

## Checks
- Operators can identify instance, version, configuration, and dependency state.
- Health signals distinguish ready from merely alive.
- Control actions are reversible or have a recovery path.

## Anti-patterns
- Logging without correlation or version identity.
- A health endpoint that reports alive while dependencies are unusable.
- Manual production changes with no audit.
