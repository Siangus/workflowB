# KU-0073: Production readiness and recovery mindset

- **book_id:** `nygard-release-it-2e`

- **lifecycle_phase:** `architecture`

## Purpose
Treat production behavior, failure recovery, and operability as design concerns rather than post-development surprises.

## Trigger
A feature is functionally complete but must face real users, traffic, dependencies, and failures.

## Procedure
1. List expected production stresses and unknown failure modes.
2. Define how the system detects, contains, and recovers from failure.
3. Expose enough state for operators and developers to diagnose behavior.
4. Test production-readiness scenarios before release.

## Checks
- Feature completion is separate from production readiness.
- Recovery and diagnostic behavior have owners and evidence.

## Anti-patterns
- Assuming all faults can be predicted and eliminated before release.
- Treating operations as someone else's concern.
