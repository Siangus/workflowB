# KU-0078: Interconnect, load balancing, and service discovery

- **book_id:** `nygard-release-it-2e`

- **lifecycle_phase:** `architecture`

## Purpose
Design the connections between instances so traffic distribution, discovery, and failure handling remain controlled.

## Trigger
A system has multiple instances, dynamic capacity, or service-to-service calls.

## Procedure
1. Define service identity and discovery source.
2. Choose load-balancing and routing behavior.
3. Handle unhealthy instances and connection limits.
4. Test traffic shift, instance loss, network delay, and stale discovery.

## Checks
- Traffic does not route to known-unhealthy instances.
- Discovery failure has bounded behavior.
- Routing and capacity assumptions are documented.

## Anti-patterns
- Treating a load balancer as a complete availability solution.
- Unbounded connection creation or stale service locations.
