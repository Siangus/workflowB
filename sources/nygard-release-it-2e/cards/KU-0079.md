## Purpose
Manage deployment, configuration, provisioning, and operational control as software with explicit ownership and visibility.

## Trigger
A system spans many instances, environments, versions, or operational services.

## Procedure
1. Separate code, configuration, and secrets.
2. Version configuration and validate it before activation.
3. Automate provisioning, deployment, and rollback.
4. Expose current configuration and control state.
5. Test control-plane failure separately from data-plane failure.

## Checks
- A deployment can reproduce the intended version and configuration.
- Invalid configuration fails before damaging production.
- Control-plane changes are auditable.

## Anti-patterns
- Editing production configuration manually.
- Deploying code without knowing the active configuration.
