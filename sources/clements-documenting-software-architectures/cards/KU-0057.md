## Purpose
Record behavior, protocols, timing, ordering, and state transitions that cannot be understood from static structure alone.

## Trigger
Correctness, concurrency, real-time behavior, failure handling, or protocol use matters.

## Procedure
1. Identify externally visible stimuli and responses.
2. Choose statecharts, sequence diagrams, use cases, message charts, or formal/trace notation.
3. Document ordering, timing, error, and timeout constraints.
4. Link behavior to components, interfaces, requirements, and tests.

## Checks
- The behavior model covers normal and exceptional paths.
- Ordering and timeout assumptions are explicit.

## Anti-patterns
- Using class structure as a substitute for runtime behavior.
- Drawing sequence diagrams without stating protocol constraints.
