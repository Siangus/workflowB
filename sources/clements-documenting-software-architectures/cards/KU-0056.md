## Purpose
Use established styles to communicate decomposition, dependency, runtime interaction, deployment, implementation, and work assignment.

## Trigger
The architecture requires a shared vocabulary for structure, behavior, runtime interaction, or environment mapping.

## Procedure
1. Select a style that matches the reasoning task.
2. Define the permitted elements and relations.
3. Document constraints and interpretation rules.
4. Provide examples and mappings to other styles.

## Checks
- The selected style does not imply unsupported behavior.
- Relations have direction and ownership where relevant.

## Anti-patterns
- Treating a style name as an architecture without defining its semantics.
- Assuming layers and deployment tiers are interchangeable.
