## Purpose
Design the system so faults can be exposed, components isolated, behavior observed, and tests executed repeatably.

## Trigger
Testing is expensive, slow, flaky, or cannot isolate architectural behavior.

## Procedure
1. Define testability scenarios.
2. Expose controlled interfaces and seams.
3. Separate test data and environments.
4. Use dependency substitution, record/replay, assertions, and deterministic clocks where appropriate.
5. Measure test execution time and diagnostic quality.

## Checks
- Important components can be tested without the whole system.
- Failures identify the responsible boundary.
- Tests are repeatable and observable.

## Anti-patterns
- Making production code depend directly on unreplaceable infrastructure.
- Using end-to-end tests to cover every internal rule.
