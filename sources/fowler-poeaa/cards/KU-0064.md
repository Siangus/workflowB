## Purpose
Choose Transaction Script, Domain Model, Table Module, or Service Layer according to domain complexity and collaboration needs.

## Trigger
A team is deciding where business rules and use-case orchestration belong.

## Procedure
1. Assess domain complexity, rule interaction, number of clients, and expected change.
2. Use Transaction Script for simple procedural operations.
3. Use Domain Model for interacting rules and rich invariants.
4. Use Table Module where logic is organized around tabular data.
5. Add a thin Service Layer when clients need a stable application boundary.

## Checks
- The choice explains domain complexity and future change.
- The selected structure keeps business rules testable.

## Anti-patterns
- Using a rich domain model for trivial CRUD.
- Putting all business logic into a service layer because it is convenient.
