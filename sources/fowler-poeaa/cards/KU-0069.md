# KU-0069: Web presentation and controller boundaries

## Purpose
Separate request handling, presentation transformation, application flow, and domain behavior so UI changes do not corrupt business rules.

## Trigger
An application exposes browser or API clients with multiple flows or presentation forms.

## Procedure
1. Separate input parsing and validation from application commands.
2. Choose Page Controller, Front Controller, MVC, Template View, or Application Controller as appropriate.
3. Keep presentation models distinct from domain models when needed.
4. Test controller routing, validation, and response behavior.

## Checks
- Presentation changes do not alter domain rules accidentally.
- Input, application, and domain errors are distinguishable.

## Anti-patterns
- Putting transaction and pricing rules in controllers.
- Returning persistence objects as an accidental public API.
