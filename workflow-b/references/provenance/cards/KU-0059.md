## Purpose
Build a coherent documentation package containing views, context, element catalogs, mappings, rationale, glossary, and completeness information.

## Trigger
An architecture must be built, reviewed, transferred, or maintained by people who were not present for its creation.

## Procedure
1. Provide a system overview and context diagram.
2. For each view, document the primary presentation, element catalog, relations, properties, and rationale.
3. Document mappings across views.
4. Maintain glossary, constraints, assumptions, and known omissions.
5. Package information by stakeholder use.

## Checks
- Readers can navigate from overview to detail and back.
- Every depicted element has supporting definition.
- Cross-view mappings are complete enough for the intended use.

## Anti-patterns
- A diagram without a key, catalog, or mapping.
- Writing documentation as a one-time delivery artifact.
