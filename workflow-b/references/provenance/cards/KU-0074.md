# KU-0074: Stability anti-pattern detection

## Purpose
Identify designs that amplify small faults into outages before they reach production.

## Trigger
Reviewing a distributed or high-load design.

## Procedure
1. Map integration points and dependency chains.
2. Find shared bottlenecks, blocked threads, unbounded queues/results, cascading failures, and force multipliers.
3. Trace what happens when each dependency slows, fails, or returns invalid data.
4. Replace or isolate the amplification path.

## Checks
- Each critical dependency has bounded time, resources, and failure behavior.
- A single failure cannot consume all shared capacity.

## Anti-patterns
- Synchronous chains without timeouts.
- Unbounded resource use.
- Many clients depending on one fragile service.
- Retries that amplify load.
