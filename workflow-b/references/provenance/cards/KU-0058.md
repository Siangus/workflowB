# KU-0058: Usage-based view selection

## Purpose
Select only the views that have a real stakeholder use, balancing documentation benefit against maintenance cost.

## Trigger
Starting or revising an architecture documentation package.

## Procedure
1. List stakeholders and the decisions they must make.
2. List anticipated uses: analysis, development, review, implementation, deployment, maintenance, or reconstruction.
3. Choose viewtypes and styles that support those uses.
4. Avoid views that no stakeholder will use.
5. Revisit the set when the architecture or audience changes.

## Checks
- Each view has an audience and intended use.
- Documentation cost is justified by a decision or activity.

## Anti-patterns
- Generating a standard view set without stakeholder demand.
- Combining unrelated views until neither concern is clear.
