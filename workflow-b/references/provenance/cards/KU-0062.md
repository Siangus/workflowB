## Purpose
Record configured variation, runtime change, optional components, and dynamic behavior so architecture decisions remain explicit.

## Trigger
A system supports plugins, configuration variants, dynamic binding, failover, hot deployment, or runtime reconfiguration.

## Procedure
1. Identify variation points and allowed values.
2. Document when and how variation is selected.
3. Document constraints, dependencies, and invalid combinations.
4. Describe runtime transitions and their impact on interfaces and deployment.

## Checks
- Variation is distinguishable from accidental implementation behavior.
- Supported runtime states and transitions have tests or operational evidence.

## Anti-patterns
- Leaving configuration or dynamic behavior implicit.
- Assuming all runtime variants receive equal validation.
