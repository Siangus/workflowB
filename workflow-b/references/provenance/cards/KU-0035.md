## Purpose
Use disposable or evolutionary prototypes deliberately to reduce requirement, UX, feasibility, and technical uncertainty.

## Trigger
A decision is expensive, ambiguous, novel, or hard to validate through discussion alone.

## Procedure
1. State the question and risk the prototype will address.
2. Choose paper, electronic, proof-of-concept, throwaway, or evolutionary form.
3. Define an evaluation script and participants.
4. Run the evaluation and record the decision.
5. Dispose of throwaway code or explicitly requalify it before production use.

## Checks
- Prototype outcome changes a decision, requirement, or risk rating.
- Stakeholders understand whether the prototype is production-bound.

## Anti-patterns
- Shipping prototype code merely because it already exists.
