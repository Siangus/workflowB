# KU-0075: Stability patterns: timeouts, circuit breakers, bulkheads, and fail-fast

## Purpose
Contain failures and prevent slow or broken dependencies from consuming the entire system.

## Trigger
A service calls remote, slow, unreliable, or resource-constrained dependencies.

## Procedure
1. Set explicit timeouts for every remote or blocking operation.
2. Use circuit breaking to stop calls to a failing dependency.
3. Partition resources with bulkheads so one workload cannot exhaust all capacity.
4. Fail fast when continuing cannot produce a valid result.
5. Define fallback or degraded behavior where the business allows it.

## Checks
- Timeouts are finite and observable.
- Open/closed circuit behavior is tested.
- Resource pools and queues are bounded.
- Fallback does not claim a false success.

## Anti-patterns
- Infinite waits.
- One global thread pool for unrelated workloads.
- Returning successful-looking data after a failed dependency.
