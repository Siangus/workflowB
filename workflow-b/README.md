# Workflow B

This is a multi-source engineering workflow generated from a lifecycle overview, requirements, domain-driven design, agile delivery, architecture quality, architecture documentation, and enterprise application pattern sources.

## Progressive Loading

Load `manifest.yaml` and `L0/` first. After selecting a state, load only the matching directory under `states/`. Enable `cross-cutting/` modules from the project profile or current risk. Load individual `L2/` methods and templates only for the current activity. Read `L3/` and the registry only for evidence, conflicts, or deep study.

```text
L0 route and decide
→ L1 current-state playbook and checklist
→ L2 method, pattern, test strategy, or template
→ L3 source evidence and provenance
```

## Control Path

1. Select a project profile in `project-profiles.md`.
2. Follow the state transition conditions in `sop-state-machine.md`.
3. Open handbook entries for methods, checklists, and source-backed tailoring.
4. Apply conflict and tailoring rules rather than treating every method as universal.

## Status

`draft-ready`: the handbook has seven L1 state playbooks, six cross-cutting indexes, and 85 L2 method files. Operations and feedback remain lighter than requirements and architecture; the current registry records the coverage honestly.
