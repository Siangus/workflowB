# KU-0060: Interface documentation

**Type:** `artifact`
**Lifecycle:** `architecture`
**Trigger:** A component, service, database, message, or external system is consumed by another party.

## Purpose
Make software interfaces stable and usable by documenting syntax, semantics, protocols, assumptions, and externally visible behavior.

## Procedure
1. Identify the interface and its stakeholders.
2. Document signatures, data types, preconditions, postconditions, effects, errors, timing, and protocol ordering.
3. Document examples and version/evolution rules.
4. Expose only stable externally visible information.
5. Link interface documentation to tests and implementation.

## Checks
- Consumers can use the interface without reading implementation.
- Error and timeout behavior is documented.
- Versioning and compatibility policy are explicit.
