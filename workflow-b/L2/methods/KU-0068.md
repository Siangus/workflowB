# KU-0068: Session state and distribution boundaries

**Type:** `decision_rule`
**Lifecycle:** `architecture`
**Trigger:** A web or service application needs user/session state or is considering remote calls.

## Purpose
Choose where state lives and where distribution occurs based on failover, payload, latency, consistency, and operational constraints.

## Procedure
1. Classify state as client, server, database, or domain state.
2. Define ownership, lifetime, sensitivity, and failover requirements.
3. Keep remote interfaces coarse-grained and explicit.
4. Prefer local calls until distribution has a measured benefit.
5. Test restart, failover, serialization, and timeout behavior.

## Checks
- State survives the required failures.
- Remote calls have documented latency and error behavior.
- Distribution reduces a real constraint rather than adding accidental coupling.
