# KU-0040: Change control and impact analysis

**Type:** `method`
**Lifecycle:** `governance`
**Trigger:** A new requirement, changed requirement, or removed requirement affects an approved baseline.

## Purpose
Evaluate, decide, implement, verify, and communicate requirement changes without silently breaking commitments.

## Procedure
1. Log the request with rationale and source.
2. Check scope alignment and analyze impacts on requirements, design, tests, schedule, cost, risk, and commitments.
3. Have the authorized decision maker accept, reject, defer, or request more analysis.
4. Implement and verify accepted changes.
5. Update baselines, links, status, and stakeholder communication.

## Checks
- Every baseline change has a recorded decision and impact.
- Commitment changes are renegotiated rather than hidden.
