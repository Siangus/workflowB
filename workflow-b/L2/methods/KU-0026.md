# KU-0026: Automated acceptance tests, TDD, and refactoring

**Type:** `method`
**Lifecycle:** `verification`
**Trigger:** Any iterative product whose changes must remain safe and affordable.

## Purpose
Maintain reliable delivery speed through two layers of automated tests and continuous design improvement.

## Procedure
1. Define business-level acceptance tests for each feature.
2. Automate regression checks for accepted behavior.
3. Use developer-level tests to expose design errors quickly.
4. Refactor continuously while tests protect behavior.
5. Repair defects immediately rather than accumulating a late test-and-fix phase.

## Checks
- New behavior has business acceptance evidence.
- Developer checks run frequently.
- Refactoring leaves behavior intact.
