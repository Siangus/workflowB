# KU-0082: Version and compatibility management

**Type:** `method`
**Lifecycle:** `release`
**Trigger:** An API, schema, message, configuration, or dependency changes while consumers remain active.

## Purpose
Evolve services, interfaces, schemas, and dependencies without forcing synchronized failure across consumers.

## Procedure
1. Identify consumers and compatibility obligations.
2. Prefer additive compatible changes.
3. Version or deprecate breaking changes explicitly.
4. Test old and new consumers during transition.
5. Remove compatibility only after migration evidence.

## Checks
- Consumer impact is known.
- Old and new versions coexist safely during migration.
- Deprecation has a date and owner.
