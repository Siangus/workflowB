# KU-0086: Software requirements specification as an implementation-independent baseline

**Type:** `artifact`
**Lifecycle:** `requirements`
**Trigger:** A project needs a technical requirement baseline for an increment or a consistent source of truth for downstream readers.

## Purpose

Organize behavior, qualities, constraints, data, and external-interface needs into a versioned baseline without dictating internal design.

## Procedure

1. Use `templates/software-requirements-specification.md` with version, scope, readers, references, and stable ID conventions.
2. Link atomic requirements to evidence, rules, models, and acceptance scenarios.
3. Specify logical data, external interface, quality, constraint, assumption, and dependency requirements.
4. Keep cross-links rather than duplicating content and baseline only the selected increment.

## Checks

- Developers and testers can determine required behavior without guessing.
- The SRS contains no unjustified architecture, physical schema, implementation, test-plan, or project-plan detail.
- Each unresolved item has an owner and construction-blocking classification.
