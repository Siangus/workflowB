# KU-0032: Clear and testable requirements

**Type:** `checklist`
**Lifecycle:** `requirements`
**Trigger:** Documenting a functional, quality, data, or constraint requirement.

## Purpose
Write requirements and requirement sets that are complete, correct, feasible, necessary, unambiguous, prioritized, verifiable, modifiable, and traceable.

## Procedure
1. Use a consistent requirement form.
2. State one observable behavior or constraint.
3. Eliminate vague and subjective terms.
4. Identify source, rationale, priority, and verification method.
5. Review the set for completeness, consistency, modifiability, and traceability.

## Checks
- A tester can derive an acceptance check without guessing.
- A change can identify affected linked artifacts.
