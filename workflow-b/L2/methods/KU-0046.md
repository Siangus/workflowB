# KU-0046: Deployability and safe rollout

**Type:** `method`
**Lifecycle:** `release`
**Trigger:** A release changes code, configuration, schema, infrastructure, or service topology.

## Purpose
Make software changes installable, reversible, and independently verifiable.

## Procedure
1. Identify deployment units and compatibility constraints.
2. Separate deployment from activation where useful.
3. Use versioning, migration compatibility, rollback or roll-forward tactics.
4. Verify the deployed artifact and its runtime configuration.

## Checks
- A release has an immutable identity.
- Rollback or forward recovery is defined.
- Schema and interface changes are compatible or deliberately coordinated.
