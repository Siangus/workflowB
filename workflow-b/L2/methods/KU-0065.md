# KU-0065: Relational data-source patterns

**Type:** `pattern`
**Lifecycle:** `design`
**Trigger:** Domain objects must be persisted to a relational database or an existing schema.

## Purpose
Isolate relational persistence choices from domain behavior and choose a mapping strategy appropriate to schema and object complexity.

## Procedure
1. Identify ownership of persistence behavior.
2. Choose Gateway, Active Record, or Data Mapper based on domain complexity and coupling tolerance.
3. Define transaction and query boundaries.
4. Profile mapping and query behavior.
5. Keep schema evolution and mapping changes reviewable.

## Checks
- Persistence mapping does not silently change domain invariants.
- Queries and transaction boundaries are observable and tested.
