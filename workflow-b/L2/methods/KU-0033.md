# KU-0033: Requirements modeling

**Type:** `method`
**Lifecycle:** `requirements`
**Trigger:** Text requirements contain complex workflows, decisions, data relationships, or stateful behavior.

## Purpose
Use visual models to reveal missing behavior, decisions, data, states, and handoffs that prose hides.

## Procedure
1. Select a model suited to the question: data flow, swimlane, state, dialog, decision table/tree, or event-response.
2. Model the problem rather than an assumed implementation.
3. Review the model with stakeholders.
4. Link model elements to narrative requirements and tests.

## Checks
- The model resolves a documented ambiguity or omission.
- Stakeholders can validate model behavior.
