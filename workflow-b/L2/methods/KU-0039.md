# KU-0039: Requirements baselines, attributes, and status

**Type:** `method`
**Lifecycle:** `governance`
**Trigger:** Requirements are approved for a release, iteration, contract, or downstream implementation.

## Purpose
Maintain an agreed requirement set through baselines, version control, stable identifiers, attributes, and lifecycle status.

## Procedure
1. Review and approve the selected requirement subset.
2. Create a named baseline and version.
3. Assign stable identifiers and essential attributes.
4. Track status from proposed through verified, deferred, deleted, or rejected.
5. Communicate the current version to all affected roles.

## Checks
- Every implementation target maps to one current baseline.
- Reported progress is based on requirement status, not guessed percentage.
