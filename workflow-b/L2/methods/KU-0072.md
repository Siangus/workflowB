# KU-0072: Base patterns for isolation and testing

**Type:** `pattern`
**Lifecycle:** `construction`
**Trigger:** Code depends on external services, configuration, money, null cases, or replaceable implementations.

## Purpose
Isolate external resources and stabilize reusable concepts through Gateway, Mapper, Value Object, Money, Special Case, Plugin, and Service Stub patterns.

## Procedure
1. Identify external or volatile dependencies.
2. Wrap them behind Gateway or Mapper interfaces.
3. Use Value Objects for domain concepts such as money and ranges.
4. Use Service Stub or Plugin to isolate tests and configuration.
5. Test the boundary and the domain behavior independently.

## Checks
- External failures are testable without requiring the real service.
- Value objects enforce domain invariants.
- Substitution does not change the intended contract.
