# KU-0049: Security as an architectural quality

**Type:** `method`
**Lifecycle:** `architecture`
**Trigger:** The system handles valuable data, privileged operations, external input, or untrusted components.

## Purpose
Protect data and operations through explicit threat, trust-boundary, access, and attack-response decisions.

## Procedure
1. Identify assets, actors, trust boundaries, and threats.
2. Define authentication, authorization, confidentiality, integrity, and accountability scenarios.
3. Select architectural tactics such as least privilege, isolation, validation, encryption, audit, and attack detection.
4. Trace controls to security tests and release evidence.

## Checks
- Every sensitive operation has an authorization decision.
- Trust boundaries and failure behavior are documented.
- Security controls have verification evidence.
