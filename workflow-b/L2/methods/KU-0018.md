# KU-0018: Anti-corruption layer and published integration language

**Type:** `method`
**Lifecycle:** `architecture`
**Trigger:** Integrating with legacy, external, or differently modeled systems.

## Purpose
Protect a local model from foreign or legacy concepts while supplying stable consumer-oriented contracts.

## Procedure
1. Define the consumer's required language and use cases.
2. Translate external data at an anti-corruption boundary.
3. Expose documented published schemas and an open host service where owning the provider.
4. Avoid exposing aggregate internals as an API.

## Checks
- Consumers do not import provider domain types.
- API resources and events satisfy consumer use cases, not internal storage shape.
